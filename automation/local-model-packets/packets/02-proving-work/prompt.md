# Draft a proving-execution request template

## Boundary

Write one complete reusable Mechanism Design process artifact from only the
embedded evidence. Do not authorize or execute a real treatment; do not create
`CMD-0001-P8`; do not invent evidence, fixture, actor, owner, authority,
condition, observation, date, decision, or result; do not choose a candidate
disposition; and do not authorize contact, transfer, graduation, deployment,
publication, or external action. The artifact is a candidate template for
Frontier verification. External action is `none`.

## Evidence

<evidence path="proving/LEAST-CONSEQUENTIAL-PROVING-PLAN-TEMPLATE.md">
A plan freezes one claim, evidence, fixture, least-consequential treatment,
falsifier, failure, bounded pass, unresolved route, standing, data, stops,
correction, recovery, permitted conclusions, and return contract. It does not
authorize execution.
</evidence>

<evidence path="proving/PROVING-AUTHORIZATION-DECISION-TEMPLATE.md">
Authorization requires an exact frozen request and plan, least-consequence
check, actor, operations, inputs, outputs, environment, validity, deviations,
stops, correction, rollback, recovery, legitimacy, and handoff. Preparation
alone creates no grant.
</evidence>

<evidence path="proving/PROVING-EXECUTION-TRACE-TEMPLATE.md">
An exactly authorized execution records frozen start state, chronological
observations, stops, deviations, evidence, affected-party and data effects,
correction, rollback, recovery, and the later score package.
</evidence>

<evidence path="GOVERNANCE.md">
Synthetic and reversible work may proceed only within an exact grant. Human,
field, institutional, incentive, consequential, account, publication, and
deployment actions remain separately gated.
</evidence>

<evidence path="ROADMAP.md">
CMD-0001 remains deferred. This is a boundary example only; do not create P8.
</evidence>

## Work now

Draft the finished Markdown artifact
`proving/PROVING-EXECUTION-REQUEST-TEMPLATE.md` with exactly these sections:

1. YAML frontmatter with `artifact_type: proving_execution_request_template`,
   `status: candidate_process_artifact`, and `external_action: none`.
2. `# Proving Execution Request Template`.
3. `## Use Boundary` separating a request from authorization, execution,
   scoring, disposition, transfer, graduation, deployment, or action.
4. `## Request Header` with fillable request, proving, plan, candidate, source,
   requester, proposed executor, authority owner, requested date, and external-action rows.
5. `## Frozen Plan And Evidence` requiring exact plan, claim, source, fixture,
   evidence, validation, environment, and prohibited inference.
6. `## Requested Treatment And Least-Consequence Case` requiring operations,
   inputs, outputs, falsifier, failure, bounded pass, unresolved route,
   alternatives including no action, discrimination, reversibility, and why no
   less consequential treatment suffices.
7. `## Requested Authority Scope` requiring actor, validity, deviations,
   correction, rollback, recovery, stop authority, and forbidden effects.
8. `## Affected Parties, Data, And Legitimacy` requiring standing,
   representation limits, risk bearers, data, retention, exposure, capture,
   consent, and who cannot be spoken for.
9. `## Stops And Start-State Checks` requiring pre-start stops, live stops,
   invalidation, last-known-good state, dependencies, and new-authorization conditions.
10. `## Prepared Request` requiring one of `ready_for_authorization_review`,
    `request_revision`, `defer`, `reject`, or `needs_judgment`, plus rationale,
    exact requested effect, non-effects, validation, next owner, and wake.
11. `## Proposed Execution Handoff` requiring trace destination, score owner,
    acknowledgment, and explicit rule that neither request nor acknowledgment authorizes execution.
12. `## Frontier Verification` listing only pre-integration and pre-authorization checks.

Use clear fillable labels such as `[required: ...]`. Return only the artifact.
