# Draft a least-consequential proving-plan template

## Boundary

Write one complete reusable Mechanism Design process artifact from only the
embedded evidence. Do not score a candidate, create `CMD-0001-P8`, invent a
fixture, add source facts, authorize a real test, prescribe a remedy, or claim
repository changes. The artifact is a candidate template for Frontier
verification. External action is `none`.

## Evidence

<evidence path="proving/README.md">
Prefer synthetic, reversible, least-consequential tests. A proving plan states
what could falsify the candidate, permitted conclusions, affected-party
standing, stop conditions, data boundary, recovery, and who owns the result.
No repository has a standing obligation to serve as proving ground. A bounded
pass does not establish effectiveness, destination fit, authority, deployment
readiness, or an external outcome.
</evidence>

<evidence path="GOVERNANCE.md">
Only synthetic and reversible work may proceed within an exact grant. Human,
field, institutional, incentive, consequential, account, publication, and
deployment actions are separately gated. Existing-owner fit defeats admission.
</evidence>

<evidence path="proving/CMD-0001-P7-counterevidence-quality-test.md#method-example">
The P7 plan freezes one adversarial trace, names an exact baseline failure and
repair pass condition, limits its conclusion, preserves source ownership,
defines recovery if the repair fails, and excludes real records, deployment,
domain remedies, and broader proving. This is a method example only; the new
template must not create another P7/P8 test.
</evidence>

<evidence path="proving/CMD-0001-P7-counterevidence-quality-score.md#claim-boundary-example">
A bounded synthetic pass may show that one named representation failure was
closed. It does not prove effectiveness, validate a real record, establish
destination fit, or authorize transfer, graduation, deployment, or broader
proving.
</evidence>

<evidence path="dispositions/README.md">
Every proving result returns to an explicit disposition: kill, revise, defer,
transfer, or propose graduation. Preserve negative evidence and reasons. A
clean prototype does not override safety, legitimacy, uncertainty, or owner
consent.
</evidence>

## Work now

Draft the finished Markdown artifact
`proving/LEAST-CONSEQUENTIAL-PROVING-PLAN-TEMPLATE.md` with exactly these
sections:

1. YAML frontmatter with `artifact_type: least_consequential_proving_plan_template`,
   `status: candidate_process_artifact`, and `external_action: none`.
2. `# Least-Consequential Proving-Plan Template`.
3. `## Use Boundary` separating plan preparation from test authorization,
   execution, scoring, disposition, deployment, or external action.
4. `## Plan Header` with a fillable Markdown table containing these exact rows:
   `proving_id`, `candidate_id`, `candidate_revision`, `source_inquiry`,
   `source_revision`, `treatment_type`, `result_owner`, `requested_by`,
   `authorization_ref`, `external_action`.
5. `## Candidate Claim Under Test` requiring one exact claim, its current
   posture, and what the test cannot establish.
6. `## Frozen Evidence And Fixture` requiring exact evidence pointers,
   revisions, fixture provenance, allowed transformations, prohibited
   inference, and a hash or other immutable boundary when available.
7. `## Treatment And Least-Consequence Rationale` allowing one primary
   treatment type from `synthetic`, `formal`, `simulation`, or `adversarial`,
   plus why a more consequential treatment is unnecessary.
8. `## Falsifier, Failure, And Pass Conditions` requiring one discriminating
   falsifier, observable failure, bounded pass, and an `UNRESOLVED` route.
9. `## Affected-Party Standing And Legitimacy` requiring represented standing,
   representation limits, who bears risk, capture concerns, and who owns any
   real-world judgment.
10. `## Data And Environment Boundary` requiring permitted data, prohibited
    data, environment, privacy/sensitivity limits, retention, and no-contact
    rule.
11. `## Stops, Kill Conditions, Correction, And Recovery` requiring immediate
    stops, kill evidence, correction owner, rollback or preservation of
    negative evidence, and the exact recovery wake.
12. `## Permitted Conclusions` distinguishing `bounded_pass`, `revise`, `kill`,
    `defer`, and `unresolved`, and explicitly excluding effectiveness,
    destination fit, transfer, graduation, deployment, and external outcome.
13. `## Score Return Contract` with a fillable table for evidence observed,
    result, counterevidence, residual uncertainty, permitted disposition, owner,
    validation, and next wake.
14. `## Frontier Verification` listing only the checks Frontier must perform
    before integrating the template.

Use clear fillable labels such as `[required: ...]`, not invented tests,
owners, sources, or results. Return only the finished artifact.
