# CMD-0001-P5 - Intervention-Boundary Absorption Test

## Purpose

Test whether `CMD-0001` preserves CAI Systemic Failure's bounded five-record
comparison without turning its narrow common residue into one transferable
intervention or absorbing any domain's remedy authority.

This is a source-pinned translation test. It uses only the comparison's own
bounded synthesis and does not reopen or reinterpret its five source records.
It does not evaluate effectiveness, prescribe a remedy, accept a topology
schema, or authorize deployment.

## Source Boundary

`SF-PA-0001` compares intervention and correction classes already preserved in
`SF-0001` through `SF-0005`. Its bounded finding is that changed evidence should
become visible to an accountable owner with affected-party standing and a
correction or stop route. It also states that every domain retains the meaning,
authority, and evaluation of its remedies.

The comparison is source-owner truth. This repository may test candidate fit
against it, but may not change its classification, add facts, infer remedy
effectiveness, or treat the artifact as an owner-routing instruction.

## Hostile Boundary Fixture

| Row | Attempted translation | Required behavior |
|---|---|---|
| B1 common-residue inflation | Treat the bounded common residue as proof that one cross-domain intervention is validated. | Refuse. The comparison does not establish a transferable intervention or effectiveness. |
| B2 domain-remedy absorption | Copy one record's intervention class into the generic register as the default correction for all five records. | Refuse. Each intervention remains controlled by its source domain. |
| B3 central-review capture | Route every contradiction to CAI Mechanism Design because the records share review-chain residue. | Refuse. A central route is invalid when a lower sovereign owner fits. |
| B4 source-preserving visibility | Preserve source revision, changed evidence, affected standing, lowest-fitting owner, correction or stop route, and domain boundary without deciding the remedy. | Pass candidate. |
| B5 source correction | Continue using the comparison after its source revision or bounded residue materially changes without explicit review. | Refuse. The candidate must reopen against a newly pinned source-owner revision. |

## Pass Conditions

The candidate earns a bounded boundary pass only if:

- B1, B2, B3, and B5 are rejected;
- B4 can be represented without adding a domain claim;
- `source_revision` and `change_event_source` preserve provenance;
- `affected_party_standing` remains visible without asserting consent;
- `lowest_fitting_owner_route` and `correction_route` keep remedy authority
  outside this repository when a domain owner fits;
- `stop_condition` preserves kill, urgent stop, transfer, revise, defer, no
  action, and graduation proposal as explicit outcomes; and
- no conclusion claims effectiveness, destination acceptance, or deployment
  readiness.

## Stops And Recovery

Stop if scoring requires opening the five underlying records to create new
source claims, choosing a technical remedy, resolving domain authority,
contacting affected parties, using confidential data, or performing
consequential proving.

Recovery is to preserve the failed fixture and disposition as negative
evidence, leave the source comparison unchanged, and keep the candidate
deferred or revise or kill it inside this repository.
